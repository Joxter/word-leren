# Инбокс сырых текстов + доступ Клоду

Статус: обсуждено 2026-08-28, не реализовано.

## Зачем

Кидать в приложение сырой инпут: кусок из книги с комментарием по-русски,
недописанное сообщение коллеге, которое пришлось перевести онлайн, фрагмент
экзамена. Внутри самому пометить места, которые вызвали сложность. Потом — в
чате с телефона, по дороге — попросить Клода посмотреть, что накопилось,
обсудить и сделать из этого карточки и примеры.

Добавляю из веба (как сейчас учу карточки), разбираю из чата. Значит доступ
Клоду нужен всегда, а не только когда открыт ноут.

## Схема

Новая сущность, не подмешивать `kind` в `lightCards`: разный жизненный цикл, а
страница Grammar работает и трогать её незачем.

```ts
// Сырой инпут: кусок книги, недописанное сообщение коллеге, что угодно.
// Разбирается потом — руками или в чате — в карточки и примеры.
inbox: i.entity({
  text: i.string(),
  createdAt: i.number().indexed(),
  // Пусто = не разобрано. Дата вместо флага: та же цена, но видно когда.
  doneAt: i.number().optional().indexed(),
}),
```

Плюс линк `inboxOwner` по образцу `lightCardOwner` и `inbox: owned` в
`instant.perms.ts`. Схему пушить **до** перм.

## Формат разметки

Обычный markdown, `**жирным**` для сложных мест, комментарий по-русски текстом
или цитатой. Никакого своего синтаксиса и никаких спанов.

Причина не в эстетике: в `examples` спаны лежат отдельно от текста офсетами, и
поэтому понадобился `anchorSpans` — иначе правка предложения ломает разметку.
Разметка внутри markdown не протухает никогда, парсить её не надо, Клод читает
её как есть, Markdoc уже подключён и отрендерит превью.

## UI

Почти копипаста флоу lightCards: `LightCardData` это ровно `{ text: string }`,
а `LightCardModal` + `MarkdocField` — готовый редактор с превью и вставкой
картинок. Нужна страница-список (неразобранное сверху) и этот же модал.

Разметку с телефона `SpanBoard` не требует — выделение markdown'ом руками.

## Доступ Клоду: MCP-сервер на дроплете

Локальный stdio-MCP не подходит: он живёт подпроцессом Claude Desktop на ноуте,
с телефона до него не достучаться вообще.

`server/mcp.mjs` — один файл:

- `StreamableHTTPServerTransport` из `@modelcontextprotocol/sdk`, stateless,
  поверх `node:http` (без express). Одна новая зависимость.
- Внутри `@instantdb/admin` (уже в devDependencies) с app id и admin-токеном.
- Авторизация — секрет в пути: `/mcp/<32 случайных байта>`.
  Потолок: кто узнал URL, тот пишет в базу, ротация руками через env и коннектор.
  OAuth-сервер ради одного пользователя не строим.
- TLS — Caddy, сертификат сам:
  ```
  mcp.<ip>.sslip.io {
      reverse_proxy localhost:8787
  }
  ```
  `sslip.io` резолвит IP из имени, домен покупать не надо. Если домен на дроплет
  уже смотрит — подставить его.
- systemd unit с `EnvironmentFile=/etc/word-leren.env` (chmod 600:
  `INSTANT_APP_ADMIN_TOKEN`, `OWNER_ID`, `MCP_SECRET`).
  Деплой = `git pull && systemctl restart`. Ни Docker, ни CI.

Тулы:

```
inbox_list   — по умолчанию только неразобранное, свежие сверху
inbox_get    — полный текст одной записи
inbox_done   — проставить doneAt
search       — карточки и примеры, чтобы не плодить дубли
create_card  — сразу в начало линии
create_example + link_span
```

`create_card` всегда кладёт карточку в начало линии, как это делает приложение.
Отдельного тула для очереди нет.

### На чём нельзя лениться

- Каждый `create` обязан ставить `.link({ owner: OWNER_ID })`. Admin SDK ходит
  мимо permissions, строка без owner не читается вообще ничем.
- Admin-токен = полный доступ ко всей базе. Только в env на дроплете, не в репе.

## Сознательно отложено

- **Картинка в `inbox`** — фотка страницы книги с телефона вероятна, но это
  `image` link в три строки, а `useImagePaste` уже написан. Добавить, когда
  реально захочется сфотографировать страницу.
- **Обратная ссылка inbox → созданные карточки** — `doneAt` плюс `search`
  отвечают на «что уже сделано». Завести, когда понадобится история.
- **Сущность для упражнений** — пока неясно, чем упражнение отличается от
  карточки или примера. Появится конкретный тип — заведём.
- **REST API** — единственный потребитель Клод, ему хватает MCP.
- **CLI `scripts/db.mjs`** — был бы нужен для локального stdio-варианта,
  при always-on сервере это второй файл с той же логикой.

## Порядок

1. Схема + пермы + страница инбокса (без них серверу нечего читать).
2. `server/mcp.mjs`, Caddy, systemd.

Перед началом выяснить: что уже занимает 80/443 на дроплете и есть ли домен,
который на него смотрит.
